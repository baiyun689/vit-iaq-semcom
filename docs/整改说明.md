# 实验代码整改与迁移说明

本轮修复实验协议与复现链路，不代表已经完成真实 CIFAR-100 重训练或验证性能提升。既有输出文件保留，不能把旧曲线直接当作新协议结果。

## 1. 新协议

- 默认 `range_policy: fixed`。ViT 预处理的均值、标准差确定归一化输入的全局固定范围；不是逐图取最小值/最大值，也不是把标准化张量当成 `[0,1]`。超出范围的数值被量化器截断，诊断输出记录数量。
- `image_minmax` 仅保留给显式元信息 IAQ 或注明理想辅助信息的参考实验。分档与 A1 入口拒绝该策略。
- 桶配置必须恰好覆盖所有图像块，且满足 `m_base <= bits <= m_max`。不能自动补桶、截桶、抬高最大位宽。
- 核心流程的 `b_target` 表示源编码的 `sum(M_i)`。六线脚本的同名参数表示总信道预算除以每块标量数；脚本会为元信息和冗余留出空间，并为桶方案设置独立源预算。
- 各方案采用同一个**总信道比特上限**，报告实际使用量；取整造成的剩余预算不伪装成已经使用。固定 `392` 源预算的桶方案使用三重复基础层保护时，会超过 `768*392` 的信道上限，必须降低源精度或提高总预算。
- 元信息真实格式为 `N*ceil(log2(m_max+1))+32` bit，默认 196 块、8 bit 上限时为 816 bit。IAQ 显式帧头仍包含两个范围字段；分档和均匀固定范围模式不需要逐图范围信息。
- 理想 IAQ 不经过信道的辅助信息另记为 `oracle_side_bits`，不称为所有方案的严格性能上界。理想线与裸传线使用相同源预算。
- AWGN 横轴为**每个实际发送的编码比特的能量/N0**；单位能量 BPSK。加入重复码后不要误写成固定信息比特能量。
- A1、分档、EEP、UEP 当前只支持 AWGN；传入 BSC 会报错。拼错模式、缺失修补网络、偶数重复码等配置不再悄悄回退。

## 2. 训练和权重

`run_repair_train.py` 使用 DataLoader 按批加载，默认将 CIFAR-100 训练集按独立的 `--split-seed`（默认 0）划分为 45000 训练样本和 5000 验证样本。默认评估其中 1000 个验证样本，不使用最终测试集选模型。`--n-test` 暂保留为 `--n-val` 的兼容别名，含义已经变为验证集数量。

修补前后使用完全相同的受损输入，输出净增益、修坏比例、救回比例和逐样本预测。训练随机种子变化不会改变验证划分。记录训练/验证索引、随机种子、批大小、软件版本、Git 版本和源码哈希。不同运行的批大小可能改变信道随机数分组，应按保存的配置复现。

新权重为 schema version 2，包含网络结构、量化范围、桶配置、基础层保护、分类器/注意力模型标识、预处理配置、训练信息和优化器状态。加载后核对协议。旧的纯 `state_dict` 权重缺少这些信息，且来自旧量化分布，会明确拒绝加载；不能仅包装为新格式继续用于正式比较。

现在每轮训练后执行配对验证，所有轮次使用相同验证样本和信道种子，验证不会消耗训练随机流。以各验证 SNR 的修补后准确率的算术平均值选择最优轮次；相同分数保留较早轮次。

- `--ckpt`（默认 `repair_net.pt`）：验证集最优模型，正式评估使用它。
- `--last-ckpt`（默认 `repair_net.last.pt`）：最近完成训练与验证的轮次，用于续训。文件还包含此前最优模型，可单文件迁移到新输出目录。
- `--out`：逐轮损失与验证指标、`best_epoch`、最佳轮次的 `curve`、最后轮次的 `last_curve`。`epochs` 是已完成轮数，`target_epochs` 是本次目标轮数。

权重与指标分别采用临时文件写完再替换，单文件写入失败不会覆盖旧文件；若进程在两个文件更新之间终止，以 `.last.pt` 为续训依据，它内含完整进度与最优模型。恢复单位是完整轮次，中途失败会从上一完整轮次重新执行。第一轮完成前没有可恢复进度。

续训恢复模型、优化器、Python/NumPy/PyTorch 随机状态、CUDA 随机状态及 DataLoader 打乱顺序。要求保留原来的数据路径、划分、批大小、进程数、设备、网络结构、训练和验证设置，仅修改目标轮数与输出位置。早期 schema 2 文件如缺少随机状态仍可用于推理，但不能精确续训。相同环境下的 CPU 小模型已验证续训与连续训练完全一致；未验证 GPU 的逐位确定性，也不保证跨硬件或软件版本一致。

在具备训练条件的机器上重新训练：

```powershell
python scripts/run_repair_train.py --device cuda --n-train 45000 --n-val 1000 --epochs 10 --batch 64 --seed 0

# 与上面配置一致，恢复最新完整轮次，训练到总计 20 轮；不是额外增加 20 轮。
python scripts/run_repair_train.py --device cuda --n-train 45000 --n-val 1000 --epochs 20 --batch 64 --seed 0 --resume outputs/corrected/repair_net.last.pt --overwrite
```

默认新输出目录为 `outputs/corrected/`。训练、六线评估、探针与配置搜索在目标已存在时拒绝覆盖，除非明确使用 `--overwrite`。训练的最佳模型、最新进度和指标文件必须使用不同路径。本轮未启动真实 GPU 训练。

重要的新诊断：

- `enhancement_assignment_error_rate`：具有增强数据的秩槽中，发送图像块和接收图像块不一致的比例。可检测同档内交换。
- `bucket_mismatch_rate`：图像块档位不同的比例，与前者不等价。
- `base_coded_bit_errors`、`enhancement_bit_errors`：信道层比特错误数量。
- `padded_payload_bits`、`unused_payload_bits`：变长 IAQ 解码异常长度。
- `input_clipped_values`：固定范围外输入的数量。

真实发送排序仅用于仿真诊断和明确标注的 oracle assignment 对照，不传给接收端或修补网络。

## 4. 结论和兼容性边界

定长结构保证读取边界不依赖接收端排序，不保证增强数据空间上局部错配，更不保证分类性能下限。零初始化残差网络仅保证初始化时恒等；有害修补必须实测。

历史 A1 脚本保留为探索参考，不作为当前同信道预算的正式主线。旧报告/旧图不会自动更新。默认固定范围会改变旧脚本的数值结果，因此任何新曲线应记录新协议，不能与旧曲线混用。

核心源码、实验公共工具与训练/评估入口做了适度整理；没有引入新的大框架，也没有增加新的修补网络架构或宣称新的实验增益。

### 显式定位对照入口

新增 `src/vit_iaq_semcom/addressed.py` 和管线 `mode="addressed"`。每个增强排名槽发送块编号与 CRC-8，编号及校验一起做三重复保护（可设其他正奇数）。编号头和增强值分别按预先约定的槽表排列，读取长度不受收到的编号影响；校验失败、编号越界或有效编号重复时擦除相应增强记录。重复编号涉及的所有记录都擦除，未获得增强的块使用基础层。CRC 只检验编号，不检验增强值；有效但错误的码字仍可能漏检。

`fit_addressed_buckets` 从最低优先级槽依次减少增强位深，直到总开销满足上限。B=392、基础层 1 bit、原候选 `98:3,98:1` 时，三重复保护下调整为 `95:3,101:1`：源载荷 296448 bit、编号 760 bit、CRC 760 bit、编号及 CRC 的重复冗余 3040 bit，共 301008 bit，上限 301056 bit，剩余 48 bit。算法是固定启发式，不声称最优位分配。

管线的 `b_target` 仍表示源位深之和，此时设置为 386；实验入口的 `--b-target 392` 表示总信道上限除以每块标量数，入口自动扣减定位开销。不能把同名参数当成相同预算层次。

```powershell
# 本机 CPU，固定验证划分，24 张真实图；三个 SNR 与三个信道种子。
python scripts/run_addressed_experiment.py --device cpu --n 24 --batch 4 --snrs 0,6,12 --seeds 0,1,2 --out outputs/corrected/addressed_20261003/comparison.json
# 已有完整结果可单独重新绘图与生成报告。
python scripts/run_addressed_experiment.py --replot outputs/corrected/addressed_20261003/comparison.json
```

六条线分别为均匀量化、原分档、候选分档、相同精度扣减后的隐式排序、显式定位与同受损载荷的 oracle 定位。后三条线的基础层/增强层受损比特完全相同。噪声由种子与样本 ID 派生，改变批大小不改变各样本随机流；与旧探针的随机流分组不同，比较必须使用本次共同重跑的结果。图中的误差条是共享样本上信道种子的总体标准差，不是泛化置信区间。

新单测覆盖无误码等价、头错误擦除、混合位宽槽不失步、重复/越界编号、CRC 漏检可观察、重复码纠错、帧长度校验、实际开销、不同批大小下的配对一致性、验证窗口边界及按图像重采样。全套离线测试 121 项通过，2 项真实权重/数据测试仍单独标记；不把单元测试数量作为性能证据。

## 7. 显式定位与均匀量化的修补训练（2026-10-03）

`run_repair_train.py --mode addressed` 会在总信道预算内调整候选桶，默认从 `98:3,98:1` 扣减为 `95:3,101:1`；`--mode uniform` 使用无元信息均匀量化。两种模式共用相同修补网络容量与训练代码，训练、验证和推理共用同一损伤入口。默认 `bucket` 模式保留。

新网络的输入是受损图、实际解码位深及两个接收端状态通道：

- 每块是否实际收到通过校验的增强记录。
- 整帧增强槽擦除比例，广播给所有块。

编号校验失败后原始位置未知，不能把发送端正确编号当成接收端的逐块擦除标签。位深停留在基础层既可能源于没有分配增强，也可能源于增强丢失，接收端不伪造二者的区分。均匀量化没有增强槽，两项状态均为零；状态嵌入结构与显式模式相同。它们不使用真实排序或真实误码标签，也不是新训练的可靠性预测器。

### 正式训练命令

以下命令供具备训练条件的另一台 GPU 机器使用，本机仍只做 CPU 小样本验证。两组设置应一起修改，保持相同样本、种子、批大小、网络、损失、SNR 范围和训练轮数。

```powershell
python scripts/run_repair_train.py --mode addressed --device cuda --n-train 45000 --n-val 1000 --epochs 10 --batch 64 --seed 0 --b_target 392 --out outputs/corrected/addressed_repair/train.json --ckpt outputs/corrected/addressed_repair/best.pt
python scripts/run_repair_train.py --mode uniform --device cuda --n-train 45000 --n-val 1000 --epochs 10 --batch 64 --seed 0 --b_target 392 --out outputs/corrected/uniform_repair/train.json --ckpt outputs/corrected/uniform_repair/best.pt
```

训练入口的 `--b_target` 表示总信道比特上限除以每块标量数，显式模式自动扣除编号和保护开销；输出同时记录源预算、实际发送比特和未使用额度。均匀模式若整除不能用满预算，会明确记录余量。旧 bucket 若添加基础层保护而超出上限，训练入口现在拒绝运行，需重新配置源位深，不能免费增加保护。

新模式每一步的 SNR 由训练种子、轮次和批序号确定，独立于信道噪声随机数消耗；因此码流长度不同也不会改变两组训练的 SNR 序列。旧 bucket 续训保留原随机轨迹。新模式仍支持最新完整轮次恢复和最佳模型保存；最佳轮次可以不同，但公平对照要求两组实际完成相同轮数。

### 四线配对评估

```powershell
python scripts/run_repair_comparison.py --device cpu --addressed-ckpt outputs/corrected/addressed_repair/best.pt --uniform-ckpt outputs/corrected/uniform_repair/best.pt --n 96 --batch 4 --snrs 0,6,12 --seeds 0,1,2 --out outputs/corrected/repair_comparison.json
python scripts/run_repair_comparison.py --replot outputs/corrected/repair_comparison.json
```

默认从固定验证划分中跳过全部模型选优用图，再取后续样本，并拒绝与修补训练/选优图重叠。使用上述默认训练设置时，从验证划分偏移 1000 开始取图；可用 `--sample-offset` 指定位置，但仍不能重叠。只有选型冻结后才使用 `--split test`；分类器曾在 CIFAR-100 训练集微调，当前验证集仍不是分类器未见过的最终测试集。

输出均匀、均匀+修补、显式定位、显式定位+修补四线。每种协议只生成一次受损输入，修补前后共用它；记录救回率、修坏率、净增益、逐样本预测、实际比特和接收状态。两种协议共享总预算上限，修补不增加传输开销。比较入口拒绝不匹配的训练样本、选优样本、种子、架构、训练轮数、损失与预算。不同协议的码流不同，不能把同一噪声种子误解成逐像素误码相同。

新权重仍使用带协议元数据的 schema 2，并增加传输模式、源预算、网格、编号保护/CRC 与收端状态定义。旧 bucket 权重仅供旧模式；不能用于 addressed+repair 或 uniform+repair，新权重也不能在旧六线入口中冒充 bucket 权重。推理可通过 `run_batch(mode="addressed+repair")` 或 `mode="uniform+repair"` 调用；显式推理须使用权重中记录的已扣减桶配置与源预算。

本轮真实 CPU 冒烟输出位于 `outputs/corrected/repair_channels_smoke_20261003/`：每种模式只训练 2 张图、验证 2 张图、1 轮、小网络，再用另外 2 张图运行四线。该目录中的权重不能作为正式实验模型；大规模训练和修补增益、状态输入等消融仍未完成。

## 8. 条件输入消融与正式训练矩阵（2026-10-03）

训练入口新增 `--conditioning full|no_depth|no_receiver|none`。消融从训练开始固定，随权重保存，加载后自动沿用；续训不允许改成另一种条件。所有参数和初始化顺序保持一致，通过屏蔽相应嵌入贡献改变可用信息，不改变传输码流。参数总量相同不等于有效条件路径相同。

| 模型子目录 | 传输协议 | 条件输入 | 训练 SNR |
|---|---|---|---|
| addressed_full | 显式定位 | 位深与接收状态 | 0–12 dB |
| addressed_no_depth | 显式定位 | 关闭位深嵌入 | 0–12 dB |
| addressed_no_receiver | 显式定位 | 关闭接收状态嵌入 | 0–12 dB |
| addressed_none | 显式定位 | 两类条件均关闭，仅受损图 | 0–12 dB |
| addressed_single | 显式定位 | 位深与接收状态 | 固定 6 dB |
| uniform_full | 均匀量化 | 相同结构；接收状态为零 | 0–12 dB |

关闭位深后，“已收到增强”状态仍可能透露部分精度信息；关闭接收状态后，位深仍可能体现增强是否可用。因此不能把单一开关称为“完全去除可靠性信息”。同时关闭两类条件才去掉这两条显式输入路径，像素本身仍可能包含量化差异。

正式配置默认三个训练种子 0/1/2、每种子六个模型，共 18 次训练，之后按种子分别进行评估。每个模型默认 45000 张训练图、1000 张选优图、10 轮、192 维/4 层修补网络；默认批大小 64，可统一改小。评估使用固定验证划分偏移 1000 后的 1000 张图，3 个信道种子、0/6/12 dB，尚不使用最终测试集。单点与跨 SNR 模型均按同一个验证 SNR 列表选优。

`--seeds` 设置训练种子；`--n-train`、`--n-val`、`--epochs`、`--batch`、`--eval-n` 会一致地作用于所有条件。不要只为某个条件单独增加训练量。不同训练种子的结果各自保留，不能把它们重复的图像当成新增独立样本。

每个输出目录包含 `plan.json`，记录参数、执行参数列表、源码与配置校验值；运行后增加 `state.json` 和逐任务日志。计划和文件路径绑定生成时的工作环境，迁移机器后应在新的输出目录重新生成计划。源码或配置改变会拒绝静默复用旧目录；纯文档修改不影响源码校验。
