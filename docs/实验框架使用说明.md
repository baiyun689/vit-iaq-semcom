# 实验框架使用说明

适用项目：`vit-iaq-semcom`。适用协议：`native-rgb-v1`。本说明对应原生 RGB 实验框架，不适用于归档中的旧脚本和旧结果。

## 1. 这个框架可以做什么

框架把一次实验写成配置文件，再按“传输方法 × 发送预算 × 训练种子 × 修补变体”生成任务。在一张指定显卡或 CPU 上依次执行训练和评价，保存完整轮次的训练状态、已完成的评价批次、逐图预测和发送开销，最后生成表格与曲线。

目前提供以下能力：

- 原生尺寸的合成图像、CIFAR-100 和 STL-10 数据入口。
- 均匀量化、重要性感知量化适配基线、显式定位分层传输三种方法。
- BPSK、AWGN、理想接收端信道信息下的块瑞利衰落；重复码和 Hamming(7,4) 对照。
- 硬重建、软重建、逐位软信息、位权不确定性和可信前缀区间。
- 无修补以及六种条件消融；CNN 或 Transformer 修补器。
- 分类器分类头训练或整网微调，修补器训练，冻结模型后的独立评价。
- 前缀置信度审查、按图像聚类的统计区间、训练种子间差异统计。

这些能力是实验工具。它们并不意味着两项拟创新已经成立，也不意味着某种方法一定提高分类准确率。正式结论需要在固定的数据划分、比较方法和统计口径下得到。

## 2. 环境和命令入口

### 2.1 使用现有环境

在项目根目录打开终端。当前机器已有的环境可以直接使用：

```powershell
& 'E:/ProgramData/Anaconda3/envs/vit-iaq-semcom/python.exe' -m pip install -e '.[dev]'
& 'E:/ProgramData/Anaconda3/envs/vit-iaq-semcom/python.exe' -m vit_iaq_semcom doctor
```

如果已经激活正确的 Python 环境，下文的命令可直接使用 `python`。`pip install -e '.[dev]'` 将当前源码以可编辑方式安装，并安装测试依赖；修改源码后不必重复安装。

`doctor` 显示 Python 路径、主要依赖版本、PyTorch 的 CUDA 信息和可见显卡。它是环境清单，不是完整显卡兼容性测试。还需要运行实际的小样本实验，确认前向、反向和显存占用符合预期。

配置为 `device: cuda` 时，如果 CUDA 不可用，程序会报错。它不会悄悄转成 CPU。需要 CPU 时，复制配置、设置 `device: cpu`，并使用新的 `output_dir`。

### 2.2 所有任务使用同一个入口

```powershell
python -m vit_iaq_semcom --help
python -m vit_iaq_semcom doctor
python -m vit_iaq_semcom validate --config configs/experiments/smoke.yaml
python -m vit_iaq_semcom plan --config configs/experiments/smoke.yaml
python -m vit_iaq_semcom run --config configs/experiments/smoke.yaml
python -m vit_iaq_semcom run --config configs/experiments/smoke.yaml --resume
python -m vit_iaq_semcom summarize --run-dir outputs/experiments/native_smoke
```

各命令的作用：

| 命令 | 用途 | 是否训练 |
|---|---|---|
| `doctor` | 查看当前环境和显卡 | 否 |
| `validate` | 检查配置字段、取值和基本约束 | 否 |
| `plan` | 生成任务矩阵和预计结果行数，保存 `plan.json` | 否，不加载数据或模型 |
| `run` | 按配置训练修补器，并在指定评价划分上评价 | `none` 不训练，其余变体训练 |
| `evaluate` | 从已完成的源运行加载冻结模型，在另一个目录评价 | 否，不重新选型 |
| `calibrate` | 在 calibration 划分上检查位概率和前缀覆盖率 | 否，不自动修改阈值 |
| `summarize` | 汇总一个运行目录中的已保存预测 | 否 |
| `fit-classifier` | 训练数据集分类器，默认仅训练分类头 | 是 |

`validate` 成功不代表权重、数据和显存都可用，也不代表每个预算都能装下协议。实际数据读取、权重加载和完整发送预算检查在运行时完成。

## 3. 先完成一次不下载数据的流程检查

```powershell
python -m vit_iaq_semcom validate --config configs/experiments/smoke.yaml
python -m vit_iaq_semcom plan --config configs/experiments/smoke.yaml
python -m vit_iaq_semcom run --config configs/experiments/smoke.yaml
```

`smoke.yaml` 使用合成 RGB 图像、小型随机分类器和短训练，目的是检查整个流程是否能够执行。它不下载 CIFAR-100，不下载预训练权重，其准确率不能写成论文性能结果。

查看 `outputs/experiments/native_smoke/run_state.json`，只有状态为 `completed` 才表示整个矩阵完成。然后查看：

- `summary/report.md`：便于阅读的结果表。
- `summary/metrics.csv`：可导入表格软件的数值。
- `summary/summary.json`：完整汇总及统计口径。
- `summary/curves_6144.png`：对应预算的准确率与配对净增益曲线。
- 各任务目录中的 `predictions.jsonl`：逐图结果及完整开销。

如果已有同名运行，不要再次执行不带 `--resume` 的 `run`。需要继续原运行时使用相同配置加 `--resume`；需要比较新配置时更换 `output_dir`。

可进一步检查其他入口：

```powershell
python -m vit_iaq_semcom run --config configs/experiments/rayleigh_hamming.yaml
python -m vit_iaq_semcom fit-classifier --config configs/experiments/fit_smoke_classifier.yaml --output checkpoints/smoke_classifier.pt
python -m vit_iaq_semcom evaluate --config configs/experiments/smoke_test.yaml --checkpoints-from outputs/experiments/native_smoke
```

`fit-classifier` 的 `--output` 和 `--out` 是同一个输出参数的两种写法。`evaluate` 的来源必须是已经完成的原始训练运行；测试配置必须与来源配置兼容。

## 4. 数据如何划分

### 4.1 五个划分各做一件事

| 划分 | 数据来源 | 允许用途 |
|---|---|---|
| `train` | 官方训练池 | 分类器或修补器的梯度更新 |
| `selection` | 官方训练池，与 train 互斥 | 选择训练轮次和最佳模型 |
| `calibration` | 官方训练池，与前两者互斥 | 置信度、前缀覆盖率及阈值审查 |
| `audit` | 官方训练池中的独立子集 | 开发期间的比较和失败分析 |
| `test` | 官方测试池 | 方案冻结后的最终评价 |

默认 CIFAR-100 研究配置为：40000 张训练、2500 张选型、2500 张校准、5000 张审查、10000 张官方测试。默认 STL-10 配置为：4000、250、250、500、8000 张。

框架按照 `data.split_seed` 产生确定性排列，按配置数量依次取得互斥子集。当前实现是随机划分，并没有做分层抽样保证每个子集的类别完全均衡。小样本结果尤其容易受类别组成影响。

`splits.json` 保存样本 ID、原始索引、数据内容摘要和划分参数。稳定 ID 例如 `cifar100:train:000123`。重复运行时会检查清单；修改种子、样本数量、数据内容或数据路径后，应使用新的输出目录。

`*_size` 表示要使用的确切数量，不是比例。真实数据的四个训练池子集总数不能超过官方训练集，测试数量不能超过官方测试集。STL-10 的未标注数据当前不参与此流程。

### 4.2 数据下载是显式选择

```yaml
data:
  root: data
  download: false
```

已有数据时保持 `false`。首次准备真实数据时，可在新的配置中设置 `download: true`，由 torchvision 下载所选数据集。该开关只管数据集，不管预训练模型权重。选择 `weights: imagenet` 或 `weights: hf:...` 时，如果权重不在本机缓存中，权重加载过程仍可能联网。

### 4.3 预训练分类器的接触范围必须单独说明

Hugging Face 上的 CIFAR-100 已训练分类器可能使用过完整的官方训练集。因此，即使本框架的修补器没有接触 audit 子集，也不能据此声称整个系统都没有见过 audit 中的图像。

本框架自己的分类器训练入口只用 train 更新参数、用 selection 选择轮次，并保存相应 ID。如果要建立分类器与修补器都遵守本地划分的主要实验，应从 ImageNet 初始权重重新训练目标分类器，再使用保存的本地 checkpoint。初始预训练权重是否接触过相关数据，仍需根据该权重来源说明。

加载本框架生成的分类器时，后续 run、calibrate 和 evaluate 会核对其已知训练、选型 ID，拒绝这些 ID 与当前 calibration、audit 或 test 子集有交集。以本地 checkpoint 继续训练时，已有的历史接触记录会累积保留，不能通过另存一个新权重文件把早期接触历史清空。通信实验应沿用分类器训练时的划分种子和子集数量；随意更换种子可能使旧训练图像落入新的审查子集，从而触发拒绝。

该保护只检查已记录的本地训练接触。外部权重的历史仍可能未知，不能因为程序没有发现交集，就声称这些权重从未见过相关图像。审查结果和分类器元数据保存在运行清单中。

不要将小样本检查配置的划分或结果混入正式配置。`cifar100_check.yaml` 用来检查加载和执行，不是正式实验的低成本替代品。

## 5. 原生通信域与分类器输入域

通信链路接收的是原生 RGB 浮点图像，取值范围 `[0,1]`：

- CIFAR-100：`3×32×32`。
- STL-10：`3×96×96`。

`transmission.patch_size` 决定通信块大小。比如 CIFAR-100 的块边长为 4 时，共有 `8×8` 个通信块；STL-10 的块边长为 8 时，共有 `12×12` 个通信块。通信块不等于 ViT 的输入 patch。

分类器适配器负责把原生图像可微上采样到 `classifier.input_size`，再按配置的 `mean/std` 标准化。干净图、受损图、修补图共用同一条处理路径。分类器参数在修补训练中冻结，但梯度可以从分类损失传回修补图。

ViT 的注意力图先取最后一层 class token 对图像 token 的多头平均，再按照空间面积重叠映射到通信网格，并归一化。这样可以在 ViT 使用 `14×14` token 网格时，为原生 `8×8` 或 `12×12` 通信网格分配重要性。

因此，发送比特数和重建失真都对应原生图像。论文中应把分类器上采样与实际发送内容分开描述，不能把上采样后的像素数当成原始数据量来扩大压缩比。

## 6. 分类器准备与使用

### 6.1 使用已有 CIFAR-100 分类器做检查

```powershell
python -m vit_iaq_semcom run --config configs/experiments/cifar100_check.yaml
```

该配置使用已有 HF 分类权重。其架构、类别数和预处理在配置中指定；它适合检查真实数据与实际分类器能否贯通。使用外部权重时，应保存权重来源，并核实它要求的预处理。

### 6.2 自建 CIFAR-100 或 STL-10 分类器

```powershell
python -m vit_iaq_semcom fit-classifier --config configs/experiments/fit_cifar100_classifier.yaml --output checkpoints/cifar100_classifier.pt
python -m vit_iaq_semcom fit-classifier --config configs/experiments/fit_stl10_classifier.yaml --output checkpoints/stl10_classifier.pt
```

默认冻结主干，只更新分类头。如果需要调整全部参数，使用新输出目录和新权重文件，并加 `--full-model`：

```powershell
python -m vit_iaq_semcom fit-classifier --config configs/experiments/fit_stl10_classifier.yaml --output checkpoints/stl10_classifier.pt --full-model
```

上面两种模式应择一开始；若已经运行过分类头模式，再改为整网模式，必须复制配置并修改 `output_dir`，不能向原目录续写。完整轮次之后中断时，原样重复命令并加 `--resume`。

分类器训练复用 `training.epochs`、`batch_size`、`lr`、`grad_accum`，种子取 `experiment.training_seeds` 的第一个值。默认以 selection 准确率选择最佳轮次，相同时比较 selection 交叉熵。它不会依据 audit 或 test 结果挑选分类器。

初始 ImageNet 主干加新的 CIFAR-100/STL-10 分类头时，目标分类头尚未训练，因此训练配置允许 `allow_random: true`。这仅用于建立分类器；正式通信实验不应以这个未训练目标分类头作为有效分类器。

### 6.3 在通信实验中加载本地分类器

CIFAR-100 可以使用 `cifar100_local_classifier.yaml`；STL-10 默认配置使用 `checkpoints/stl10_classifier.pt`。主要字段如下：

```yaml
classifier:
  kind: vit
  arch: vit_base_patch16_224
  weights: random
  checkpoint: checkpoints/cifar100_classifier.pt
  input_size: 224
  mean: [0.485, 0.456, 0.406]
  std: [0.229, 0.224, 0.225]
  allow_random: false
```

这里的 `weights: random` 只是创建网络结构时的初始化选择，随后会完整、严格地加载 checkpoint；它不表示最终使用随机权重。

本框架生成的 checkpoint 保存架构、模型类型、类别数、输入大小、均值、标准差和训练接触记录。加载时会检查这些元数据与配置一致。不要仅替换权重路径而沿用另一个权重来源的标准化参数。

外部纯 `state_dict` 可以加载，但其元数据标注为外部未知，框架无法从中判断正确预处理或训练接触范围。严格加载参数只能说明张量名称和尺寸匹配，不能说明实验设置正确。

## 7. 三种传输方法和发送预算

### 7.1 预算统一表示实际发送比特

`experiment.budgets` 表示每幅图最多发送的编码后 BPSK 符号数。本实现一个符号携带一个编码比特，因此实际 `channel_uses` 等于 `total`。

```yaml
experiment:
  methods: [uniform, iaq, addressed]
  budgets: [6144, 12288, 24576]
```

每幅图记录以下可相加项目：

| 字段 | 含义 |
|---|---|
| `payload_bits` | 量化像素载荷，不含纠错冗余 |
| `position_bits` | 显式定位字段，包括块编号和位平面编号 |
| `depth_metadata_bits` | IAQ 各块位深字段 |
| `crc_bits` | 元信息校验位 |
| `padding_bits` | 分组编码所需填充 |
| `fec_bits` | 重复码或 Hamming 编码产生的冗余 |
| `total` | 以上六项之和，不能超过预算 |
| `unused` | 预算减实际发送量 |

`header_bits` 是位置、位深和 CRC 的小计，不能再次加到 `total` 上。预算小于最低可发送内容时程序报错；不同方案因整块或整层粒度不同，可能留下不同数量的未使用比特。应同时报告预算上限和实际使用量。

量化使用共享 `[0,1]` 范围和逐层二进制前缀，不为每幅图发送最小值、最大值。网格、预算、编码方式和基础位深等属于预先共享的协议配置，当前没有模拟会话建立和配置协商开销。

### 7.2 `uniform`：所有块使用相同位深

根据预算选择能够完整发送的最大统一位深，按共享顺序发送像素量化位。它不需要逐图位深头部。未达到下一整层的剩余预算不会被使用。

### 7.3 `iaq`：重要性分配与受保护的位深头部

重要性越高的通信块，在边际量化收益准则下更优先获得额外位深。发送各块位深、CRC32 和像素载荷。

头部经过重复保护并实际计费。接收端检查 CRC、位深范围以及总位深是否符合预先确定的容量。头部无效时，该帧无法安全解析自适应载荷，接收内容被擦除；头部偶发未检错误仍可能造成错误解析。

这是本框架对 IAQ 思路的原生域适配基线，不应直接称为原论文代码的逐项复现。

### 7.4 `addressed`：固定基础层与显式位平面槽

基础层按共享位置顺序发送。增强部分由固定长度的槽组成，每槽只有一个通信块的一层增强位平面，头部包含：块编号、位平面编号和 CRC8。

头部失败的槽被擦除；多个有效头部指向同一个“块、位平面”组合时，这些重复记录全部擦除。错误编号不会改变后续槽的边界，但未被 CRC 检出的错误仍可能将内容放到错误位置。接收端不使用真实块编号来偷偷纠正这类错误。

这与旧实现中一条增强记录可能包含多层载荷的设计不同。新框架的预算、槽数、接收证据和结果对应 `native-rgb-v1`，不能把历史曲线和新结果直接拼在同一张表里当作同协议比较。

### 7.5 保护参数的作用范围

```yaml
transmission:
  m_max: 8
  m_base: 1
  code: repetition
  header_repetition: 3
  payload_repetition: 1
  base_repetition: 1
```

- `uniform` 和 `iaq` 的像素载荷使用 `payload_repetition`。
- `addressed` 的基础层使用 `base_repetition`，增强载荷使用 `payload_repetition`。
- 元信息头部始终使用重复码，重复次数为 `header_repetition`。
- `code: hamming74` 改变像素载荷编码；头部仍使用重复码。载荷重复次数作用在编码后的比特上。

保护更强会挤占可发送的图像信息。不能只比较“加了更多保护后准确率变化”，而不同时核算剩余载荷和总发送量。

## 8. 信道、软证据和修补消融

### 8.1 信道设置

```yaml
transmission:
  channel: awgn
  code: repetition
  decode: soft
  noise_mismatch_db: 0.0
  prefix_threshold: 0.99
experiment:
  snrs: [-4, -2, 0, 2, 4, 6, 8, 10, 12]
  channel_seeds: [0, 1, 2]
```

SNR 是单位能量实数 BPSK 的编码比特能量与噪声谱密度之比。它不按码率折算为每个未编码信息比特的能量。不同编码比较时，应保持此定义并同时报告发送次数。

`rayleigh` 使用每幅图共享的平坦块衰落增益，接收端知道真实增益。当前没有导频、信道估计误差或 CSI 获取开销。因此该设置应写作“理想接收 CSI 下的块瑞利衰落”。

`noise_mismatch_db` 改变接收端用于计算软信息的噪声假设，不改变实际加噪。正值表示接收端假设的信噪比更高，容易产生更强的自信。

`decode: hard` 和 `decode: soft` 分别选择硬判决重建、按接收位概率重建。要比较两者，应使用两个新运行目录并保持其他设置一致；所有修补变体在同一配置下必须使用同一种起始重建。

Hamming(7,4) 是短码对照，使用有效码字枚举形成硬判决和边际位概率。它不等同于现代 LDPC 强基线。

### 8.2 接收证据的含义

| 证据 | 含义与限制 |
|---|---|
| `depth` | 实际收到的位数图，描述精度，不等同于正确概率 |
| `llr` | 接收观察得到的对数似然比，正值支持比特0 |
| `bit_prob` | 比特为1的边际概率 |
| `bit_mask` | 哪些位实际收到；缺失位为0 |
| `uncertainty` | 按二进制位权计算的数值不确定性近似 |
| `prefix_lower/upper` | 满足当前置信条件的连续高位前缀所限定的区间 |
| `prefix_confidence` | 在假设的信道模型下形成的前缀置信界 |

缺失位使用 mask=0、LLR=0、概率0.5；不能把没有收到的位当作“非常可靠的0”。位级证据按颜色、从高到低的位平面排列，形状为 `3*m_max × H × W`。

`diagnostics` 中的真实误码、未检头部错误和真实覆盖情况仅用于离线统计，不进入修补网络。对于编码引入的比特相关性，数值不确定性使用边际近似；对于错误位置关联，像素位的软信息也不自动包含定位正确概率。

### 8.3 七种变体

| `repair.variants` | 输入和作用 |
|---|---|
| `none` | 直接使用接收重建，不训练修补器 |
| `image` | 只看受损图像 |
| `depth` | 图像与位深 |
| `llr` | 图像、位深以及按颜色聚合的简单 LLR 条件 |
| `bitwise` | 图像、位深、逐位 LLR/概率/缺失掩码 |
| `uncertainty` | 在 bitwise 基础上加入数值不确定性 |
| `prefix` | 在 uncertainty 基础上加入前缀区间与置信度，并可使用前缀损失 |

六种可训练变体使用相同网络结构和参数量，通过屏蔽不同证据组做消融。`none` 是恒等映射，不属于同参数量网络。模型初始残差头为零，初始输出等于输入；训练之后仍可能修坏原本分类正确的样本。

当前 prefix 使用置信度加权的软区间惩罚，不是硬投影，也不保证输出永远满足前缀。高置信度但错误的前缀可能产生错误约束，必须报告这种风险。

### 8.4 修补训练参数

```yaml
repair:
  variants: [none, image, depth, llr, bitwise, uncertainty, prefix]
  architecture: transformer
  dim: 96
  depth: 2
  heads: 3
training:
  epochs: 20
  batch_size: 8
  grad_accum: 4
  lr: 0.0003
  snr_min: 0.0
  snr_max: 12.0
  lambda_task: 1.0
  lambda_mse: 0.1
  lambda_prefix: 0.1
  lambda_identity: 0.0
```

每个训练批次从给定范围取一个信噪比。损失由分类交叉熵、重建 MSE、可选前缀约束和可选干净图恒等约束组成。`lambda_task` 控制分类损失权重；设为0并保留正的 `lambda_mse`，可以训练像素损失对照。前缀项仅作用于 prefix 变体。修补器按 selection 上的准确率选择轮次，相同准确率时比较重建 MSE。

分类器被冻结，但仍需保存其前向过程中用于输入梯度的计算信息。显存不足时，先降低批量并用 `grad_accum` 保持所需有效批量，再建立新运行目录。不要假设“分类器不训练”就几乎不占显存。

正式模板采用小批量8、累积4次，完整累积组对应32个样本。这是起始配置，不是对任意显卡显存和吞吐的保证；最后一个不足完整组的批次会按实际样本数处理。

## 10. 校准、审查与冻结最终测试

### 10.1 校准是在独立子集上测量可信程度

```powershell
python -m vit_iaq_semcom calibrate --config configs/experiments/cifar100_repair.yaml
```

输出为对应目录的 `calibration.json`。命令始终读取 calibration 划分，不读取 test 来选择阈值。它检查配置阈值以及0.9、0.99这组候选值，重复值合并。对每个候选阈值重新生成其可接受的最长连续前缀，不只是筛选另一个阈值已经形成的区间。

主要观察：

- `empirical_prefix_coverage`：已经接受的前缀区间中，实际包含原像素的比例。
- `acceptance_fraction`：有信息的前缀被接受的比例。
- `mean_accepted_interval_width`：接受区间的平均宽度。
- `bit_brier_score`、`bit_confidence_ece` 和可靠性分箱：接收位概率的误差与校准情况。

这些统计中的像素、颜色和信道重复存在相关性，不能把所有计数当作独立试验计算极窄置信区间。位概率校准情况也不等于整个前缀的正确率，应同时看实际前缀覆盖率。

该命令不会自动替你选择阈值，不会改写配置，也不会保证阈值0.99就对应99%的真实正确率。决定阈值时应留下选择依据，再用冻结的设置训练或评价。

注意：`calibrate` 会建立运行清单。若要继续在同一配置、同一目录运行训练，使用 `run ... --resume`。如果根据校准修改了 `prefix_threshold`，应使用新的配置及输出目录；不能在已有模型目录直接覆盖传输设置。

### 10.2 最终测试使用冻结的源运行

```powershell
python -m vit_iaq_semcom evaluate --config configs/experiments/cifar100_test.yaml --checkpoints-from outputs/experiments/cifar100_repair
```

请将 `--checkpoints-from` 改成实际完成训练的输出目录，并检查测试配置的继承来源。这个命令不训练、不重新选择最佳轮次，只加载各源任务的 `best.pt`。

冻结评价要求：

- 来源是已完成的原始训练运行，不能是另一次 evaluate 的输出。
- 新评价使用不同 `output_dir`。
- 源码、协议、数据划分、分类器及修补器结构保持一致。
- 方法、预算、训练种子、变体可以取源矩阵的子集，不能增加未训练组合。
- 可以更改评价划分、评价信噪比、信道种子和 bootstrap 次数。
- 默认不允许改变传输配置；通过下一节的显式开关，只能额外改变信道类型和接收噪声假设。
- 传输编码、前缀阈值、训练损失、预处理和数据子集数量仍须一致。

不同编码、保护次数或量化结构仍不能借此开关改变。它们涉及协议和训练输入的变化，需要另外设计相应实验与兼容规则。

为了使最终 test 与训练运行的划分清单一致，应在训练开始前就确定 test_size。最终测试阶段不能临时改成另一套样本数量，再称其为同一冻结实验。

测试中断时：

```powershell
python -m vit_iaq_semcom evaluate --config configs/experiments/cifar100_test.yaml --checkpoints-from outputs/experiments/cifar100_repair --resume
```

不要通过把训练配置的 `split` 改成 test 再调用 `run` 来替代冻结测试。那样会重新建立训练生命周期，不能体现严格的冻结过程。

### 10.3 同一冻结模型的信道泛化测试

如果研究问题是“在 AWGN 下训练的模型，换成瑞利衰落后是否仍然有效”，应保留源模型，不在目标信道重新训练。使用 `--allow-channel-shift` 显式允许两项变化：`transmission.channel` 和 `transmission.noise_mismatch_db`。

```powershell
python -m vit_iaq_semcom evaluate --config configs/experiments/cifar100_rayleigh_test.yaml --checkpoints-from outputs/experiments/cifar100_repair --allow-channel-shift
python -m vit_iaq_semcom evaluate --config configs/experiments/cifar100_mismatch_test.yaml --checkpoints-from outputs/experiments/cifar100_repair --allow-channel-shift
```

前一个模板把信道改成 `rayleigh`；后一个模板将接收端噪声假设偏移设为 +2 dB，实际加噪模型保持来源设置。两者均加载原运行的最佳模型，不重新训练、不依据目标测试数据重新选择轮次。模板继承的其他配置仍必须与实际源运行一致。

先检查这个入口时可运行：

```powershell
python -m vit_iaq_semcom evaluate --config configs/experiments/smoke_shift.yaml --checkpoints-from outputs/experiments/native_smoke --allow-channel-shift
```

该合成模板同时改变上述两项，只用于流程检查。论文实验宜分别改变信道和噪声假设，再增加二者同时改变的组合，以分辨误差来源。

运行清单保存源参数、目标参数以及是否启用该开关。若不加开关却修改这些字段，程序会拒绝；恢复同一泛化评价时，需要保留相同开关并加 `--resume`。该开关不放宽数据隔离、模型来源、预算子集或 checkpoint 完整性检查。

目标信道上的结果只能用于报告冻结模型的泛化表现。若看过目标测试结果后又修改方法，应重新区分开发数据和最终保留测试，不能继续把原测试当作未使用过的最终证据。

## 11. 断点恢复与目录完整性

### 11.1 修补器训练

`latest.pt` 保存完整轮次的模型、优化器、随机状态、历史和最佳模型。中断发生在某轮中间时，该轮会从上一完整轮次重新执行，不是从任意 minibatch 继续。

已完成任务会校验模型文件摘要。配置、执行源码、数据划分和分类器权重发生变化时，恢复会被拒绝。不要手工修改清单中的指纹来绕过检查。

### 11.2 评价

每个完整评价批次原子保存到 `evaluation_batches/`。恢复时检查其签名、样本 ID 和结果摘要，跳过已经完成的批次。`predictions.jsonl` 是从这些批次重建的汇总文件，不是唯一的恢复依据。

因此，不要只保留 `predictions.jsonl` 然后删除批次文件，还期望原运行能够可靠恢复。需要归档完整实验时，应保留运行清单、划分、状态、模型和批次记录。

### 11.3 分类器训练

分类器恢复也以完整轮次为单位，检查配置、相关源码、初始权重、数据划分以及模型张量摘要。已经完成的导出 checkpoint 还会检查文件 SHA-256。

进行中的分类器训练可能先写出新的最佳权重，再提交本轮恢复状态。恢复时，以已提交的 `classifier_latest.pt` 为准重建导出文件，并在报告中记录该操作。

这些检查用于发现误用、意外修改和损坏，不是针对恶意同时改写文件及校验值的安全机制，也不能保证操作系统或磁盘故障下绝无数据损失。

### 11.4 常见报错如何处理

| 报错或现象 | 处理方式 |
|---|---|
| 运行目录已经存在 | 同一实验加 `--resume`；新实验改 `output_dir` |
| 配置或源码指纹不一致 | 保留旧运行，建立新目录；不要篡改指纹 |
| 数据不足或下载被关闭 | 检查 `data.root`；需要下载时显式设置 `download` |
| 分类器预处理不匹配 | 对照 checkpoint 元数据修正 `input_size/mean/std` |
| 真实数据使用随机目标分类器 | 准备有效权重；仅流程检查可显式允许随机分类器 |
| 预算无法容纳基础层或头部 | 增大预算或调整合法协议参数，并重新建立运行 |
| CUDA 不可用 | 修复环境或明确建立 CPU 配置 |
| 显存不足 | 在新配置中减小 batch、调整累积次数或模型尺寸 |
| 汇总提示记录不足 | 检查 `run_state.json`，恢复未完成任务，不把局部结果当完整矩阵 |

## 12. 结果和统计口径

```powershell
python -m vit_iaq_semcom summarize --run-dir outputs/experiments/cifar100_repair --bootstrap-samples 10000
```

该命令只汇总一个运行根目录，不能把多个独立运行目录直接套在一个父目录下混合统计。

每条预测对应：方法、变体、预算、信噪比、训练种子、信道种子和稳定样本 ID。字段包含真实类别、干净预测、修补前预测、修补后预测、失真指标、总发送量、各项开销和离线诊断。

主要指标的定义：

| 指标 | 含义 |
|---|---|
| `accuracy` | 修补后分类正确比例；none 分支就是接收重建的正确比例 |
| `before_accuracy` | 同一批受损图在修补前的正确比例 |
| `clean_accuracy` | 相同分类器对干净原生图的正确比例 |
| `gain` | 修补后减修补前，属于同一图像、同一次受损输入的配对差值 |
| `rescued_rate` | 原来错、修补后对，占全部评价记录的比例 |
| `harmful_repair_rate` | 原来对、修补后错，占全部评价记录的比例 |
| `mse`、`psnr`、`ssim` | 原生 RGB `[0,1]` 域的重建质量 |
| `total_bits_mean/max` | 实际编码后发送量的均值和最大值 |
| `training_accuracy_sd` | 不同已训练模型的准确率样本标准差 |

`gain` 不是相对于另一个传输方法的差值。例如 addressed/prefix 的 gain 表示它相对 addressed 的同一次接收重建变化，不能直接当作相对 uniform 的改进。

当前 bootstrap 先在每幅图内部平均信道种子和已训练模型重复，再按图像抽样，报告条件于这些已训练模型的95%分位数区间。它不会把同一幅图的多个噪声版本当作多张独立图。完整的训练不确定性并没有全部包含在该区间中，因此同时报告训练种子标准差。

CSV 中准确率和 gain 为0到1范围的比例。阅读报告中的 gain 使用百分点。PSNR 是逐图 dB 值的平均，零失真以数值上限处理；它不等于先平均 MSE 再转换成 dB。SSIM 的窗口、边界与常数写入运行清单，跨实现比较时应核对定义。

运行还记录按批观测的耗时和 CUDA 峰值分配显存。计时没有专门的热身和独占设备基准流程，分类耗时包括干净、修补前、修补后三次分类，不应直接当作单次部署端到端延迟。

论文的表格和曲线应从固定运行的输出生成，并保留配置、来源清单及脚本版本。合成或随机分类器运行会标注为流程检查，不能作为创新收益证据。

## 13. 产物布局

```text
outputs/experiments/<运行名>/
  plan.json                  任务矩阵与预计结果行数
  run_manifest.json          配置、协议、源码、数据和分类器指纹
  run_state.json             总运行状态
  splits.json                数据划分和稳定样本 ID
  events.jsonl               运行事件
  calibration.json           执行 calibrate 后的审查结果
  jobs/<方法>/budget_<预算>/seed_<训练种子>/<变体>/
    state.json               单任务状态和产物摘要
    latest.pt                可训练分支的最近完整轮次
    best.pt                  可训练分支的最佳模型
    history.json             逐轮训练及选型记录
    events.jsonl             单任务事件
```

none 分支没有训练权重；冻结评价目录主要保存新评价记录及源运行身份。分类器训练的运行目录另有 `classifier_fit.json`、`classifier_latest.pt` 和 `splits.json`，最终权重保存在 `--output` 指定位置。

模型文件可能很大，尤其是整网分类器训练需要同时保留当前状态、优化器及最佳状态。正式实验开始前，应预留数据、训练状态和逐图结果所需磁盘空间。

| 模块 | 扩展位置 |
|---|---|
| `framework/config.py` | 新配置字段、默认值和严格验证 |

| `framework/cli.py` | 对外命令 |

新增方法时，应同步做四件事：定义输入输出和配置；将所有真实发送字段加入预算；把接收证据与仿真真值分开；建立针对预算、缺失信息、配对输入与恢复行为的测试。

两项拟创新可分别从以下位置继续研究：

- 在 transport 的固定预算约束下，用可测的定位失败代价和数值失真代价替换当前启发式分配，比较保护策略、实际开销和有效载荷。
- 在现有位级证据和 prefix 接口上，研究更准确的数值不确定性与约束方法，同时比较简单 LLR 条件、无前缀条件和普通图像修补。

当前重要性分配仍是边际量化收益启发式；框架还没有证明联合定位风险分配达到最优，也没有自动实现完整的风险校准策略。新增模块必须在真实比较中体现贡献，不能仅凭多输入通道或多一个损失项认定创新成立。

## 16. 正式论文实验仍需补齐的研究证据

框架交付后，可以开始系统实验，但以下内容仍需研究与验证：

- 有足够任务性能的目标分类器，以及清楚的数据接触范围。
- 与候选创新接近的方法、强纠错基线和合理的预算利用对照。
- 不同预算、信道和数据集上的稳定结果，而非单个信噪比的偶然优势。
- 多训练种子的结果，并分别报告修补救回和修坏的样本。
- 前缀约束的实际正确率、覆盖范围及错误高置信情况。
- 计算、发送量、模型容量和分类器处理过程一致的公平比较。
- 对现有协议假设的说明：预共享配置、理想 CSI、CRC 未检错误和相关比特的不确定性近似。

先用清楚的对照回答一个具体问题，再扩展矩阵。能够运行完整矩阵只是开始；论文需要证明方法为什么有效、何时失效，以及收益来自哪一部分。
