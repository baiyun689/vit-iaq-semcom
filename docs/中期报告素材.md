# 中期报告素材：重要性感知语义通信的元信息脆弱性与抗级联编码方案

> 本文档为填写《中期报告-白云飞.doc》提供素材，按报告模板各章节组织。
> 论文题目建议：**"重要性感知语义通信中元信息脆弱性分析与抗级联编码方法研究"**

---

## 选题来源

语义通信的核心目标是：在有限带宽下，将信源中对下游任务最关键的信息高效、鲁棒地传输至收端。实现这一目标存在两条技术路径。其一为**隐式表征路径**：以端到端联合信源-信道编码（JSCC）为代表，通过自编码器学习固定维度的隐变量，将压缩与抗噪联合优化。该路径可实现端到端最优，但属黑箱范式，依赖大量端到端训练，且隐式表征难以解释。其二为**显式重要性感知路径**：利用预训练模型的先验知识（如 ViT 注意力、显著性检测器等）识别信源中不同区域对下游任务的重要性，据此进行差异化资源分配。该路径的吸引力在于无需端到端训练、分配过程可解释、即插即用。

然而，显式重要性感知路径存在一个尚未被系统性分析与解决的结构性障碍：差异化分配必然产生描述"如何分配"的元信息；当该元信息通过噪声信道传输时，由于变长码流结构，元信息差错将引发收端解析游标失步，进而导致后续内容从错误位置读取——全局结构性崩塌，而非渐进退化。这一"**元信息级联脆弱性**"使显式路径的鲁棒性始终受制于元信息传输的可靠性，构成了该路径从理论方案走向实际部署的关键瓶颈。

本课题聚焦上述结构性矛盾，提出「**非级联源编码 + 收端语义修补**」的解决方案：在通信层面，通过非级联粗桶编码结构使级联失步在结构上不可能发生；在 AI 层面，通过任务驱动的收端修补网络零额外带宽地修复残余局部损伤。课题以 ViT 注意力驱动的图像分类传输为验证载体，在 CIFAR-100 上开展系统性实验验证。

## 一、学位论文研究目标及研究内容

### 研究背景

随着 6G 通信向"面向任务"范式演进，语义通信不再以比特级无损为唯一目标，而是追求在有限带宽与噪声信道下优先保障对下游任务关键的信息。在此背景下，如何识别信源中的"语义重要性"并将有限传输资源向其倾斜，成为核心问题。

当前语义通信实践可归为两条技术路径。**隐式表征路径**以端到端 JSCC 为主流：编解码器联合学习从信源到信道符号再到任务输出的映射，重要性判断隐式嵌入网络权重。该路径在重建与分类任务上取得了显著进展，但其黑箱性质带来三个固有代价：(1) 依赖大规模端到端训练，更换任务或信源需重新训练；(2) 资源分配逻辑不可解释，难以审计与调试；(3) 隐式表征维度固定，难以对信源内容变化做结构性适配。

**显式重要性感知路径**则采用不同的设计哲学：借助预训练模型的先验知识显式评估各信源区域对下游任务的重要性，并据此差异化分配传输资源（如比特、功率、带宽）。该路径的优势包括：无需端到端训练（直接复用预训练模型的先验）、分配过程可解释（重要性来源于注意力或梯度等可审计信号）、即插即用。这些特性使显式路径在高动态、多任务、资源受限的边缘部署场景中具有独特吸引力。

然而，显式路径引入了一个结构性代价：差异化分配必须伴随元信息——描述"哪个区域分配了多少资源"的辅助数据——以便收端正确解析。在实际无线信道中，该元信息同样经受噪声干扰。由于差异化分配通常产生变长码流（不同区域获不同比特数 → 载荷被切分为不同长度的段 → 收端需元信息标记各段边界），元信息中的任何一个比特差错都可能使收端游标偏移到错误位置，导致后续所有段从错误位置读取——**一个比特的差错可造成整个信源的全局结构性崩塌**。本文将这一现象定义为"**元信息级联脆弱性**"。

元信息级联脆弱性的实质是一种结构性缺陷，而非某个具体方案实现上的疏忽。只要同时满足 (a) 差异化分配、(b) 变长码流、(c) 元信息过信道三个条件，该脆弱性就存在。因此，消除该脆弱性的根本途径不在于"把元信息保护得更好"（概率性缓解），而在于改变源编码结构本身——使码流解析不再依赖元信息的正确性。

### 研究目标

1. **系统性揭示**显式重要性感知语义通信中的元信息级联脆弱性，形式化分析变长码流在噪声信道下的级联失步机理，并通过定量实验表征其崩塌特征与触发条件。
2. **提出非级联粗桶源编码框架**，在保留动态重要性分配优势的前提下，从源编码结构上消除级联失步的可能性，使信道差错仅造成局部损伤而非全局崩塌。
3. **设计收端任务驱动语义修补网络**，利用分类任务损失训练轻量修补器，在零额外带宽条件下将粗桶编码的残余局部损伤补回，实现优雅退化。

### 研究内容

**创新点 1（语义通信 · 源编码）— 抗级联重要性感知编码**：

- 形式化分析变长编码在噪声信道下的级联失步机理：元信息角色 → 游标推进逻辑 → 单点差错扩散路径。
- 提出非级联粗桶编码框架：基础层（每区域固定比特均匀量化，定长定位置，解码不依赖任何元信息）+ 增强层（固定大小固定比特的桶，码流按桶配置定长排布，收端游标推进仅依赖已知的桶配置常数，不依赖"哪个区域在哪个桶"）。
- 收端从基础层重建图派生重要性排序并入桶，实现重要性信息在收发两端的免传输同步。
- 关键性质：(1) 游标步长由桶配置唯一确定 → 结构上永不失步；(2) 派生排序与发端不一致 → 仅局部值错配，绝不级联扩散。

**创新点 2（AI · 学习式错误隐藏）— 任务驱动收端语义修补**：

- 设计轻量 patch-Transformer 修补网络：输入受损重建图 + 比特深度可靠性图（桶解码过程的免费副产品，标记各区域实得比特数），输出残差修正。
- 三个核心设计原则：(1) 可靠性感知——比特深度 Embedding 注入各区域 token，使低可靠性区域重点依赖上下文修复；(2) 任务损失驱动——以分类交叉熵为主损失直接训练，避免代理目标（如"逼近干净图注意力"）与真实任务目标背离；(3) 残差兜底——head 零初始化保证未训练时输出恒等，结构上保证 AI 不帮倒忙。
- 训练策略：冻结分类裁判与 patch_embed，仅训练修补网络；跨 SNR 随机采样训练单一网络；仅收端运行，零额外带宽开销。

### 技术路线

建立实验基线（ViT 注意力提取 → 差异化比特分配 → 均匀量化 → 数字信道传输 → 分类）→ 分别在 BSC 和 AWGN 信道下量化元信息过信道的崩塌效应 → 发现并表征级联悬崖 → 设计非级联粗桶编码替代变长编码 → 设计并训练修补网络 → 六线对照实验（含消融）验证方案有效性。验证载体：CIFAR-100 图像分类，ViT 注意力驱动的显式重要性感知传输。

### 2.2 创新点 1：元信息级联脆弱性的发现与形式化（已完成）

**核心发现**：
在显式重要性感知传输中，收端解析载荷码流依赖描述每区域比特深度的元信息来确定切分位置。信道噪声翻转元信息中的任何一个比特 → 游标读取错误数量的比特 → 从该区域起，后续所有区域的比特边界全部偏移 → 全局重建崩塌。这不是渐进退化，而是**断崖式崩溃**。

**实验证据（已产出）**：

| SNR | 差异化+裸传元信息 准确率 | 粗桶 准确率 | 差异化 SSIM | 粗桶 SSIM | 关键现象 |
|-----|------------------------|-----------|------------|----------|---------|
| 0dB | 3.1% | 19.1% | **0.070** | **0.543** | 差异化方案结构全毁，53/196 元信息值错 + 归一化参数从 1.0 跳变到 -8.99 |
| 3dB | 5.5% | 17.2% | **0.149** | **0.638** | 27/256 张差异化方案图 SSIM 为**负数**（反相关），粗桶零负值 |
| 6dB | 40.6% | 6.2% | — | — | 元信息暂未损坏时差异化方案尚可，但一旦触发立即崩 |

**SSIM 分布分析（3dB，n=256）**：
- 差异化+裸传元信息：均值 0.149，最小值 **-0.193**，**27 张图像（10.5%）SSIM < 0**
- 粗桶：均值 0.638，最小值 +0.266，**零负值**

负 SSIM 表示重建图与原图呈**反相关**——级联崩坏不止是"加噪声"，而是系统性地颠覆了图像的空间结构。

**传统方案对比分析（已完成理论论证）**：
- CRC+ARQ 重传：语义通信延迟敏感场景不适用
- UEP/FEC 强保护：概率性方案，无法从结构上消除悬崖；FEC 膨胀从载荷预算内扣
- 固定码率（均匀分配）：放弃重要性自适应红利（14pt 增益）

### 2.3 创新点 1：非级联粗桶源编码方案（代码已完成，部分实验待跑）

**已完成模块**：

| 模块 | 功能 | 代码文件 | 单测 |
|------|------|---------|------|
| 粗桶编解码 | 基础层定长 + 增强层定长定位桶 + 收端派生排序 | `bucket.py` | 11 passed |

**方案原理**（代码实现完毕）：

1. **基础层**：每 patch 固定 m_base bit 均匀量化，定长、固定位置。解码不依赖任何排序/元信息。提供粗图先验 + 收端派生排序的来源。

2. **增强层**：按注意力降序将 patch 填入固定大小固定比特的桶（例：top-49→4bit，次-49→2bit，其余→1bit），增强码流按桶配置定长排布。收端游标推进**只看桶配置（已知常数），不看"哪个 patch 落在哪里"**。

3. **收端派生排序**：解基础层 → 在基础层重建图上算注意力 → 降序入桶 → 定长解增强层。

**关键性质**（代码验证通过）：
- 游标步长由桶配置唯一确定 → 结构上永不失步
- 派生排序与发端不一致 → 仅局部值错配，不级联扩散
- 均匀量化嵌入式性质：T bit 索引的高 m_base 位 = m_base bit 索引 → 基础层 + 增强层重组 = T bit 精度

### 2.4 创新点 2：任务驱动收端语义修补网络（代码已完成，训练待跑）

**已完成模块**：

| 模块 | 功能 | 代码文件 | 单测 |
|------|------|---------|------|
| 修补网络 | patch-Transformer + 残差兜底 + 推理接口 | `repair.py` | 6 passed |
| 训练脚本 | 跨 SNR 训练、分类 CE+MSE 损失、冻结分类器 | `scripts/run_repair_train.py` | CPU 冒烟通过 |

**网络架构**（刻意轻量，约 3M 参数）：
- patch embed (768→192) + 比特深度图 Embedding + 位置编码
- 4 层 TransformerEncoder (dim=192, heads=3, FFN=768)
- head 零初始化 → 初始输出=输入 → 残差兜底

**三个设计原则**：
1. **可靠性感知**：比特深度图免费标记各 patch 可信度，经 Embedding 注入
2. **任务驱动训练**：分类交叉熵为主损失，避免代理目标失配
3. **安全兜底**：残差 + 零初始化 → 最坏情况 = 退回基础层地板

**与粗桶编码的协同关系（已通过 SSIM 实验验证）**：
- 粗桶提供结构化损伤（非完全垃圾）→ 修补网络有可信上下文
- 粗桶提供免费可靠性图 → 告诉修补器修哪里
- 基础层提供质量地板 → 残差兜底有稳定下界

目前实际研究方向（显式重要性感知语义通信中的元信息脆弱性与抗级联编码）与原开题方向（面向图像重建与分类的端到端 JSCC 方法研究）在研究路径上存在差异：原开题计划沿"隐式表征"路径，通过 DCT 频域增强与轴向自注意力改进端到端 JSCC 编解码器；实际工作转向了"显式重要性感知"路径，在复现与分析该路径代表性方案的过程中发现了元信息级联脆弱性这一结构性问题，并提出了非级联粗桶编码与收端语义修补的解决方案。研究仍处于语义通信大领域内，以图像分类传输为任务场景，核心脉络从"编解码器结构改进"调整为"发现并消除显式路径的结构性障碍"。
